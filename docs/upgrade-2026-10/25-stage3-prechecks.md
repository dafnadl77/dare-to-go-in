## 1. השאילתות המבוקשות על Supabase החי (ממתינות לאישורך, לא הורצו)

**מה כל השאילתות קוראות:** רק את קטלוג המסד, כלומר מבנה, הרשאות, מדיניות, טריגרים, אילוצים, הגדרות פונקציות ומשימות מתוזמנות.
**מה הן לא קוראות:** אף שאילתה לא קוראת שורה מ-`dreams`, מ-`dream_attempts` או מכל טבלה אחרת. אין בהן תוכן חלומות, אימיילים, מזהי משתמשים או ספירות.

**איך יורצו:** דרך מחבר Supabase, כל שאילתה בתוך טרנזקציה לקריאה בלבד. כך שגם טעות לא יכולה לכתוב:
```sql
begin transaction read only;
-- השאילתה
commit;
```

**Q1. האם RLS פעיל בשתי הטבלאות**
```sql
select c.relname, c.relrowsecurity, c.relforcerowsecurity
from pg_class c join pg_namespace n on n.oid = c.relnamespace
where n.nspname = 'public' and c.relname in ('dreams', 'dream_attempts');
```
**Q2. מדיניות ה-RLS על `dreams`** (מותר לעדכן? רק את השורות של הבעלים?)
```sql
select policyname, permissive, roles, cmd, qual, with_check
from pg_policies
where schemaname = 'public' and tablename = 'dreams'
order by policyname;
```
**Q3. הרשאות טבלה על `dreams`**
```sql
select grantee, privilege_type
from information_schema.role_table_grants
where table_schema = 'public' and table_name = 'dreams'
order by grantee, privilege_type;
```
**Q4. הרשאות ברמת עמודה על `dreams`** (למשל, אם מותר לעדכן רק את `favorite`)
```sql
select grantee, column_name, privilege_type
from information_schema.column_privileges
where table_schema = 'public' and table_name = 'dreams' and grantee in ('anon', 'authenticated')
order by grantee, column_name, privilege_type;
```
**Q5. טריגרים על `dreams`** (שלא יחסמו או ישנו עדכון של ה-payload)
```sql
select t.tgname, pg_get_triggerdef(t.oid)
from pg_trigger t
where t.tgrelid = 'public.dreams'::regclass and not t.tgisinternal;
```
**Q6. העמודות של `dream_attempts`** (שמות בלבד, בלי ערכים)
```sql
select column_name, data_type, is_nullable, column_default
from information_schema.columns
where table_schema = 'public' and table_name = 'dream_attempts'
order by ordinal_position;
```
**Q7. אילוצי CHECK על `dream_attempts`** (האם יש תקרה על `label_count`)
```sql
select conname, pg_get_constraintdef(oid)
from pg_constraint
where conrelid = 'public.dream_attempts'::regclass and contype = 'c'
order by conname;
```
**Q8. ההגדרות של פונקציות המונים** (שהתקרה של `label_count` אכן מגיעה מהפרמטר `p_max`, ושההחזר מוריד מונה אחד בלבד)
```sql
select p.proname, pg_get_function_identity_arguments(p.oid) as args, pg_get_functiondef(p.oid) as definition
from pg_proc p
where p.pronamespace = 'public'::regnamespace
  and p.proname in ('reserve_labels_attempt', 'refund_labels_attempt', 'reserve_reflection_attempt', 'refund_reflection_attempt')
order by p.proname, args;
```
**Q9. משימות מתוזמנות** (שאף משימה לא מוחקת שורות `dream_attempts`, כי המשך מהארכיון נשען עליהן)
```sql
select jobname, schedule, command from cron.job order by jobname;
```

**מה נדע מהתוצאות**
- Q7 ו-Q8 קובעים אם אפשר להרחיב את המכסה בלי מיגרציה (אפשרות א).
- Q1 עד Q5 קובעים אם הדפדפן יכול לעדכן חלום שכבר נשמר. אם לא, צריך פונקציית SQL ייעודית, שהיא מיגרציה, ואחזור אלייך.
- Q9 מאמת שהמשך מהארכיון אפשרי. לפי הקוד שבריפו (`20261005_purge_expired_analysis_results.sql`), המשימה המתוזמנת רק מנקה את `analysis_result` ולא מוחקת שורות.

## 4. בלי קריאות AI מיותרות

**חזרה לרגע שכבר נחקר**
- השאלה, התשובה, ההבהרה והתובנה נקראות מהמצב השמור.
- הכפתור "לחקור את הרגע" מוצג רק לרגע שלא נחקר.
- מכונת המצבים מתעלמת מבקשה לחקור רגע שכבר נחקר, או רגע שיש עליו קריאה פתוחה.

**פתיחת המפה מהארכיון**
- הכול נבנה מה-payload השמור, בלי שום קריאת AI. הצבעים מחושבים מהתמונה בדפדפן.
- **חריג אחד שכבר קיים היום:** בממשק האנגלי, שדות עבריים מתורגמים דרך `dream-translation` (gpt-4o-mini), וכיום רק כותרות ותוויות נשמרות במטמון. יוסף מטמון גם לשאר השדות, כך שפתיחה חוזרת לא תתרגם שוב. בממשק העברי אין שום קריאה.

**המבט השלם**
- נוצר רק בלחיצה.
- נשמר לפי `basedOn` (הרגעים והתשובות שעליהם נכתב). אותו קלט מחזיר את המבט השמור בלי קריאה.
- כפתור העדכון מופיע רק כשנוסף רגע.
- הכפתורים ננעלים בזמן שקריאה פתוחה.

**איך זה ייאכף:** בדיקות שסופרות קריאות רשת עם fetch מדומה:
- פתיחת מפה שמורה: 0 קריאות.
- פתיחה חוזרת של רגע שנחקר: 0 קריאות.
- שתי לחיצות על "לגלות": קריאה אחת.
- עדכון בלי רגע חדש: 0 קריאות.

## 5. מסע חלקי: שמירה והמשך אחרי רענון או יציאה

**המצב היום** (נבדק בקוד): עד הלחיצה על "לשמור" שום דבר לא נשמר. ברענון הכול אובד, ויש רק אזהרה לפני יציאה. נשמרים רק טקסט החלום לפני הניתוח, לשעה, ומפתח שמונע חיוב כפול.

**ההצעה: עותק מקומי של המסע הפתוח, בדפדפן הזה בלבד (IndexedDB)**
- **מה נשמר:** הוא מתעדכן אחרי כל צעד, ושומר:
  - תוצאת הניתוח ו-`attemptId`.
  - הרגעים, התוויות והשאלות.
  - כל תשובה, הבהרה ותובנה.
  - הרגשות והמבט השלם.
  - **התמונה האחת שכבר נוצרה.**
  - גם טקסט שהתחלת להקליד ועוד לא שלחת, אחרי שתי שניות בלי הקלדה.
- **בחזרה** (רענון, לשונית שנסגרה או יום אחר בתוך תקופת השמירה) מופיעה ההודעה "יש חלום שלא הסתיים. להמשיך?":
  - **"להמשיך"** מחזיר בדיוק לנקודה שבה עצרת: המפה, או השאלה של הרגע הפתוח עם הטקסט שהוקלד.
  - **"לא"** מוחק את העותק.
- **בלי קרדיט נוסף ובלי תמונה נוספת:** ההמשך משתמש באותו `attemptId` ובתמונה השמורה. הניתוח לא רץ שוב.
- **קריאה שהייתה באמצע בזמן הרענון:** התשובה נשמרה מקומית **לפני** הקריאה, ולכן לא אובדת. הקריאה נשלחת שוב בהמשך, וזו קריאה אחת נוספת בתוך המכסה.
- **מתי העותק נמחק:**
  - אחרי שמירה מוצלחת, כי מאז הרשומה בחשבון היא המקור.
  - ב"לשחרר" וביציאה מהחשבון.
  - אחרי תקופת שמירה שאת תקבעי (הצעה: 7 ימים).
  - הוא קשור למזהה החשבון, ולכן חשבון אחר באותו דפדפן לא רואה אותו.
- **אחרי השמירה הראשונה:** כל צעד נוסף מתעדכן ברשומה בחשבון. העותק המקומי נשמר רק עד שהעדכון אושר. המשך ממכשיר אחר אפשרי דרך הארכיון.
- **מגבלה:** לפני השמירה הראשונה, המשך אפשרי רק באותו דפדפן.
- **דורש אישורך:**
  1. שורה במדיניות הפרטיות (עברית ואנגלית), ברשימת אחסון הדפדפן: "חלום שבתהליך עד שנשמר או נמחק". אכין נוסח ולא אשנה טקסט משפטי בלי אישור.
  2. תקופת השמירה.
- **חלופה שאני לא ממליץ עליה:** שמירה אוטומטית בשרת לפני שבחרת לשמור. היא שומרת תוכן חלום בחשבון בלי בחירה מפורשת, ומשנה את המשמעות של "לשחרר".
