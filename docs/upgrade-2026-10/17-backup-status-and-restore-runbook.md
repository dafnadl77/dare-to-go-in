**מועד גיבוי אחרון מאומת:** אין גיבוי מלא שאפשר להצביע עליו בשעה ובשם קובץ. מה שמאומת הוא שהשרת מעלה כרגע (19:22 UTC) קטעי WAL ללא כשל, וזו התשתית שממנה בונים שחזור לנקודת זמן. זה **לא** מחליף הוכחה שהגיבוי היומי שלם.

**מה אפשר לשחזר (לפי המבנה):** כל הטבלאות בסכמה `public`, חשבונות Auth (אם ה־dump כולל את סכמת `auth`, **לא מאומת**), והגדרות המסד (פונקציות, RLS, אינדקסים) שנוצרו במיגרציות. קבצי התמונות רק מארכיון ה־`storage`.

## 2. מה חסר, בסדר עדיפות

1. **צילום מסך מ־Supabase: Database ← Backups** (רשימת הגיבויים והתאריך האחרון, וכן אם PITR מופעל). זה סוגר את סעיף Supabase.
2. **צילום מ־GitHub: Actions של המאגר הפרטי**: שמות ה־workflows, 10 הריצות האחרונות והתוצאה. וצילום של הדלי ב־B2 (שמות ותאריכי הקבצים האחרונים, בלי ערכים). זה סוגר את סעיף B2.
3. **האם יש התראה על כשל**: ב־GitHub, Settings ← Notifications (התראות Actions), וב־Backblaze התראות על הדלי. לא ידוע.
4. **היכן שמור מפתח age הפרטי** ואם יש לו עותק מחוץ ל־GitHub (בלעדיו ה־dump אינו ניתן לפענוח, וזה סיכון גדול).
5. **שחזור ניסיוני אחד** לפי סעיף 4 (תרגיל חד־פעמי, אחרי שיש מידע).

## 4. נוהל שחזור חירום

**עיקרון:** לעולם לא משחזרים ישירות על מסד הייצור. משחזרים לפרויקט Supabase חדש (או לקונטיינר מקומי למסד בלבד), מוודאים, ורק אז מחליפים.

1. **עצירה ותיעוד.** מתעדים מה קרה ומתי. אם יש נזק בנתונים, מפסיקים כתיבה (מכבים את האתר זמנית או מציבים הודעת תחזוקה). לא מוחקים דבר.
2. **בחירת נקודת שחזור.**
   - עדיפות א: PITR או גיבוי יומי של Supabase (Database ← Backups ← Restore), אם זמינים. Supabase משחזר לפרויקט חדש כשבוחרים כך.
   - עדיפות ב: הקובץ האחרון `dump.age` מ־B2 (תיקיית `database`) + ארכיון `storage` מאותו יום.
3. **פרויקט יעד נקי** (דורש אישור: ייתכן שיש עלות). מקבלים כתובת, מפתח שירות ומפתח ציבורי חדשים.
4. **שחזור המסד.** מפענחים את `dump.age` במחשב או בהרצה זמנית (`age -d -i key.txt dump.age`), ואז `pg_restore`/`psql` על היעד. סדר חשוב:
   1. סכמות `auth` ו־`storage` (המשתמשים והמטא־דאטה של הקבצים). בלי `auth.users` כל `owner_id` יתום.
   2. סכמת `public` (טבלאות, אילוצים, פונקציות, RLS) ואז הנתונים.
   3. מיגרציות שלא נכללו, לפי `supabase/migrations/` בקוד.
5. **שחזור הקבצים.** מעלים את ארכיון ה־`storage` לדלי `dream-images` (פרטי, מגבלה 5MB) באותם נתיבים `<מזהה משתמש>/<קובץ>`. המטא־דאטה כבר ב־`storage.objects` מהשלב הקודם.
5א. **החזרת הרשאות (חובה, לפני שמחברים את האתר).** הגיבוי הלילי נעשה עם `--no-privileges`, כלומר ה־GRANT וה־REVOKE **אינם בו**. בפרויקט Supabase חדש הפונקציות של התשלום, הקרדיטים והמנהלת היו נפתחות לברירות המחדל. מריצים את `docs/upgrade-2026-10/restore/restore-grants.sql` (משחזר בדיוק את מצב הייצור: 33 פונקציות לשירות בלבד, RLS בכל הטבלאות) ובודקים ששלוש שאילתות האימות בסופו מחזירות 0 שורות.
6. **הגדרות שאינן ב־dump** (ידני, ראו doc 12 סעיף 2): הגדרות Auth בלוח (Site URL, כתובות הפניה, Google OAuth, SMTP ותבניות מייל), משתני סביבה ב־Vercel, ה־webhook ב־Make ו־Grow, ו־DNS.
7. **בדיקות תקינות** (SQL לקריאה בלבד על היעד; כולן רצו בהצלחה על הייצור):
   ```sql
   select (select count(*) from auth.users) users, (select count(*) from public.dreams) dreams,
          (select count(*) from public.payment_orders) orders, (select count(*) from public.credit_ledger) ledger,
          (select count(*) from storage.objects) files;
   -- יתרות מול יומן: חייב להיות 0
   select count(*) from public.dream_credits c where balance <> (select coalesce(sum(delta),0) from public.credit_ledger l where l.owner_id=c.owner_id);
   -- הזמנה מזוכה ללא שורת יומן: חייב להיות 0
   select count(*) from public.payment_orders o where o.status='granted' and not exists (select 1 from public.credit_ledger l where l.external_ref='grow:'||o.provider_tx);
   -- פונקציות התשלום והמנהלת קיימות
   select proname from pg_proc where proname in ('complete_payment_order','grant_credits','is_dream_admin','admin_list_paid_orders');
   ```
   ובנוסף: התחברות בחשבון בדיקה, פתיחת חלום קיים עם תמונה, ואימות שכתובת תמונה חתומה נפתחת.
8. **חיבור האתר ליעד.** מחליפים ב־Vercel (production): `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, ופורסים מחדש. מעדכנים ב־Make/Grow רק אם כתובת ה־webhook של DARE השתנתה (היא לא תשתנה).
9. **אחרי הכול:** בודקים הרשמה, חלום חינמי וקריאת יתרה, ואין רכישה אמיתית עד שהכול תקין. מתעדים מה שוחזר ועד איזה זמן אבדו נתונים.
