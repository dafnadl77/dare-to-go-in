## 1. מפת הארכיטקטורה הנוכחית

### מסע אחד, לפי הסדר (קריאות AI)

| # | שלב | נתיב | מודל | חיוב ומכסה |
|---|---|---|---|---|
| 1 | תמלול (בקול בלבד) | `/api/dream-transcription` | whisper-1 | מוגבל קצב: 6 לדקה ו-40 לשעה |
| 2 | ניתוח | `/api/dream-analysis` | gpt-4o-mini | **כאן יורד הקרדיט**, באופן אטומי עם יצירת `dream_attempts` (`start_user_attempt_idem`). כישלון מחזיר את הקרדיט פעם אחת בדיוק |

- כל קריאה מאחורי הקרדיט נרשמת מול `attemptId` של החלום. בדיקת הבעלות נעשית ב-SQL, וכישלון של ספק ה-AI מחזיר את המקום במונה (`refund_*`).
- ב-production יש אילוץ CHECK: `image_count` ו-`reflection_count` בין 0 ל-3. אי אפשר להגדיל אותם בלי מיגרציה. `reserve_labels_attempt` מקבל את התקרה כפרמטר (`p_max`), ולפי המיגרציה של הבעלים אין עליו אילוץ. **יש לאמת זאת בקריאה בלבד מול המסד לפני שמסתמכים על זה.**
- יש 12 פונקציות Vercel, וזו התקרה. כל קריאה חדשה חייבת לעבור דרך פונקציה קיימת עם `mode`, כמו שכבר נעשה עם `questions`.

### המסע בממשק (`src/hero/HeroDream.tsx`, 1064 שורות)
ניתוח → תמונה (אישור או "לא בדיוק" עם תיקון) → פורטל → "מה בולט לך?" → **בחירה של רגע אחד** מתוך עד 6 (`deriveDreamElements`) → שאלת אסוציאציה (נכתבה מראש לכל הרגעים) → שאלת קישור אופציונלית (גם היא **נכתבה לפני התשובה**) → רגשות (אופציונלי) → פרשנות אחת → סגירה: לשמור או לשחרר.

### שמירה וארכיון
- החלום נשמר **רק בסוף**, כרשומה אחת שלמה: `dreams(id, owner_id, created_at, favorite, payload jsonb)`. השמירה עוברת דרך `saveDreamRemote`, שמבצע upsert עם `ignoreDuplicates` ולכן לעולם לא מעדכן רשומה קיימת. אין בקוד שום נתיב שמעדכן את `payload` (רק `favorite`).
- ב-payload אין שדה גרסה. התאימות לחלומות ישנים נשענת על כך שכל שדה חדש אופציונלי.
- לא נשמרים: רשימת הרגעים, השאלות, הרגעים שלא נבחרו ו-`attemptId`.
- רענון או יציאה באמצע מסע: הכול אובד. יש רק אזהרה לפני יציאה (`unsavedJourney`, `beforeunload`). הטקסט שנכתב נשמר רק לפני הניתוח (`dreamDraft`).
- הארכיון (`DreamDetail.tsx`) לקריאה בלבד: אין המשך ואין הרצה מחדש.
- `pattern-reflection` קורא מה-payload רק את `dreamAnalysis`, `selectedElement` ו-`dreamReflection.observation`. השדות האלה חייבים להישאר במקומם.
- מחיקת חלום או חשבון מוחקת את השורה כולה, כולל כל ה-payload. שדות חדשים בתוך ה-payload נמחקים אוטומטית.

## 2. השינויים הנדרשים למסע רב-רגעים

### הזרימה החדשה
1. היצירה נשארת כמו היום: ניתוח, **תמונה אחת**, אישור או תיקון לפי המנגנון הקיים, פורטל.
2. מסך "מה בולט לך?" נשאר (הכניסה המאושרת). הבחירה הראשונה פותחת את חקירת הרגע הראשון.
3. **חקירת רגע:**
   - **שאלה.** ברגע הראשון אין עדיין תשובות קודמות, ולכן השאלה שנכתבה מראש היא שאלה כנה. מהרגע השני והלאה נכתבת שאלה **בזמן הבחירה**, עם כל התשובות שכבר ניתנו, ולכן היא באמת מותאמת. אם הקריאה נכשלת מוצגת השאלה הקבועה. היא לא מוצגת כ"מותאמת", ונרשם `questionSource` כדי לדעת מאיפה היא באה.
   - **קריאה אחרי התשובה.** מחזירה תובנה ממוקדת לרגע, ולצידה **שאלת הבהרה רק אם היא מוסיפה מידע חדש**. אם לא, מוחזר `null`. זה פותר את הבעיה הנוכחית ששאלת הקישור נכתבת לפני התשובה. המודל מקבל את התשובה ואת ההוראה "אל תשאל על מה שכבר נאמר", ובנוסף יש בדיקה בקוד שחוסמת חפיפה גבוהה עם התשובה.
   - **שאלת הבהרה.** אפשר לדלג עליה. בדילוג מוצגת התובנה שכבר נוצרה, בלי קריאה נוספת. אם נענתה, נוצרת קריאה אחת שמעדכנת את התובנה.
   - בסוף: "לרגע הבא" או "חזרה למפה".
4. **הרגשות**: נשארים צעד אופציונלי, **פעם אחת לחלום**, אחרי הרגע הראשון, כמו היום. מכאן הם עוברים לכל הקריאות הבאות.
5. **המפה**: מופיעה אחרי הרגע הראשון. מוצגים כל הרגעים שהוצעו. רגע שנחקר מואר עם התובנה, רגע שלא נחקר עמום ואפשר לחקור אותו. אין חובה לעבור על כולם.
6. **המבט השלם**: הכפתור "לגלות את התמונה השלמה" זמין מרגע אחד שנחקר. הקריאה מחליפה את הפרשנות הנוכחית ומקבלת את כל הרגעים שנחקרו. היא מחזירה: התבוננות כוללת, קשרים בין רגעים (כל קשר עם מזהי שני רגעים ו"בסיס", כלומר ציטוט מהחלום או מהתשובות), נושא או רגש שחוזר **רק אם חזר**, הבדל או סתירה, עד 2 קריאות פרשניות כשהעומק מצדיק זאת, ושאלה מסכמת. הקשרים מאומתים בקוד: שני המזהים קיימים ונחקרו, והבסיס מעוגן בטקסט (`groundedText`). קשר שלא עובר את הבדיקה נמחק ולא משוכתב.
7. **שמירה**: הכפתור "לשמור את החלום" (טקס השמירה הקיים) זמין במפה מהרגע הראשון שנחקר. אחרי שמירה, כל רגע או מבט שלם נוסף נשמרים אוטומטית לאותה רשומה.

### מבנה הנתונים (ב-payload, ללא מיגרציה: שדה אופציונלי חדש `exploration`)
```ts
exploration?: {
  version: 1;
  attemptId: string;                 // מאפשר המשך מהארכיון על אותה מכסה
  moments: { id: 'm1'..'m6'; label: string; excerpt: string | null }[];   // כל מה שהוצע
  explored: Record<MomentId, {
    status: 'exploring' | 'explored';
    question: string; questionSource: 'pregenerated' | 'adaptive' | 'fixed';
    answer: string;
    followUp?: { question: string; answer: string | null };   // null = דילוג
    insight: { observation: string; reflection: string; possibility: string };
    order: number; exploredAt: string;
  }>;
  synthesis?: { basedOn: string /* hash של הרגעים והתשובות */; momentIds: string[]; generatedAt: string;
                overview; connections: { from; to; basis; kind }[]; recurring | null; contrast | null;
                readings: { basis; reading }[]; closingQuestion; generations: number };
}
```
- `excerpt` הוא משפט מתוך טקסט החלום המקורי שמכיל את הרגע. הוא נבחר בקוד, בלי AI, ואם אין התאמה הוא `null`. הקלפים לא ממציאים תיאור.
- **תאימות:** `selectedElement`, `reflectionResponse` ו-`dreamReflection` ממשיכים להתמלא. הם נלקחים מהרגע הראשון שנחקר ומהמבט השלם, אם קיים, ולכן הארכיון הישן, `pattern-reflection` והכותרות לא נשברים. חלום בלי `exploration` נפתח בדיוק כמו היום.
- גודל: 6 רגעים מלאים ומבט שלם מוסיפים בערך 10 עד 20 KB לרשומה.

## 3. תוכנית טכנית למפת החלום

### קומפוננטות (חדשות, `src/map/`)
- `mapLayout.ts`: פונקציה טהורה (מספר רגעים, רוחב, כיוון) → משבצות. נבדקת ביחידה. דסקטופ: 1 = רגע אחד מתחת לתמונה ובצידה, 2 = ימין ושמאל, 3–4 = פינות, 5–6 = שלוש בכל צד. מובייל: מסלול אנכי. **מספר הצמתים בא מהנתונים**. אין ארבעה קבועים.
- `DreamMap.tsx` ו-`DreamMap.css`: CSS Grid (צד, מרכז, צד). התמונה האחת במרכז, במסגרת עגולה עם זוהר. במובייל היא בראש.
- `MapLinks.tsx`: שכבת SVG עם `aria-hidden` ו-`pointer-events:none`. הנקודות נמדדות מה-DOM (`ResizeObserver`), כך שהקווים נמתחים בין שולי הכרטיסים ולא חוצים טקסט. שני סוגי קווים, בבירור:
  - **קו מבני** (תמונה ← רגע): רק "הרגע הזה שייך לחלום", בלי טענה.
  - **קו קשר** (רגע ↔ רגע): מופיע **רק** אם המבט השלם החזיר קשר מאומת, ואת הבסיס שלו אפשר לקרוא בפוקוס או במעבר עכבר.
- `MomentCard.tsx`: מספר, כותרת, `excerpt`, משפט התובנה המרכזי ותווית סטטוס (טרם נחקר, בחקירה, נחקר). כל כרטיס הוא כפתור אמיתי. **טקסט בלבד, בלי תמונות.** מותרים רק אייקוני SVG קטנים.
- `MomentDetail.tsx`: דיאלוג נגיש (מלכודת פוקוס, Esc) שמציג את השאלה, התשובה, ההבהרה והתובנה המלאה.
- `WholeView.tsx` ו-`ConnectionsList.tsx`: מתחת למפה. הקשרים מוצגים גם כרשימת טקסט, כך שקורא מסך מקבל את כל המידע בלי ה-SVG.
- נגישות: `<ol>` של כפתורים, פוקוס גלוי, `aria-label` עם המספר והסטטוס, RTL ו-LTR דרך CSS logical properties, ומספור שמתהפך נכון.

### עיצוב: נאמנות לקונספט ולמיתוג
- רקע: וידאו העננים המאושר (`dream-stage-clouds.mp4`, `DreamStageBackground`) עם הכוכבים הקיימים, **לא** תמונת רקע שטוחה.
- גוני הזוהר באים מהפלטה שכבר מחולצת מתמונת החלום (`extractDreamPalette`) ומהזהב של המיתוג. הפונטים Fraunces ו-Heebo, והצבעים מ-`index.css`.
- קריאות: הכרטיסים על לוחות כהים אטומים כמעט, כמו `ReadablePlates.css`, עם יעד ניגודיות 4.5:1 לפחות. רצפת הטקסט 15px נשמרת.
- **סטיות מכוונות מהקונספט, לאישורך:**
  1. בכרטיס מוצגת **התובנה** והשאלה עוברת לפרטי הרגע. בקונספט מופיעה השאלה.
  2. הטקסט "הדלת כסמל להזדמנות חדשה" שבקונספט מנוגד לכלל "בלי מילון סמלים". הטקסטים במפה ייווצרו וייבדקו כמו כל הטקסטים.
  3. בפאנל "רגעים נוספים לחלום" שבקונספט יש "הערות אישיות" ופעולות נוספות. אלה **פיצ'רים חדשים** (אחסון ופרטיות) שלא נכללו בבקשה. אבנה רק: לקרוא את החלום שוב, מועדף (קיים) ולחקור עוד רגעים.
  4. הטקסטים הקטנים בקונספט יוגדלו ל-15px לפחות.
- אנימציות (CSS ו-SVG בלבד, בלי WebGL): התמונה מופיעה בהדרגה, קווי האור נבנים (`stroke-dashoffset`), צומת נדלק אחרי חקירה, והמבט השלם נחשף בעדינות. בחלום טעון החשיפה שקטה יותר. עם `prefers-reduced-motion` הכול מופיע מיד.

## 4. השפעה על נתונים, קרדיטים ועלויות

### מחיר וחיוב: ללא שינוי
- נשאר **קרדיט אחד לחלום שלם**, שיורד בניתוח, כמו היום. אף קריאה חדשה לא נוגעת ביתרה.
- כישלון מחזיר את המקום במונה ולא את הקרדיט, כי הקרדיט שייך לניתוח. **אין מסלול לחיוב כפול.**

### מכסות לחלום: שתי אפשרויות
- **אפשרות א (מומלצת לשלב הראשון, בלי מיגרציה):**
  - הקריאות החדשות לרגעים עוברות על המונה `label_count`. התקרה עולה מ-3 ל-16 (פרמטר בקוד).
  - המבט השלם עובר על `reflection_count`, ששלושת המקומות שלו כבר לא משמשים לפרשנות הישנה. כלומר: מבט ראשון, עדכון אחד וניסיון חוזר.
  - תנאי: אימות **בקריאה בלבד** שאין CHECK על `label_count` ב-production. אבקש אישור לפני השאילתה.
- **אפשרות ב:** מיגרציה עם מונים נפרדים (`moment_call_count`, `synthesis_count`), סקריפט rollback ובדיקות PGlite. נקי יותר למדידה, אבל זה שינוי במסד ה-production.

### מניעת קריאות כפולות ו-cache
- כל קריאה נושאת מפתח: `attemptId` ומזהה הרגע וסוג הקריאה. התוצאה נשמרת ב-state וב-payload, וחזרה לרגע שכבר נחקר **לא קוראת שוב**.
- המבט השלם מזוהה לפי `basedOn` (hash של הרגעים והתשובות). אותו קלט מחזיר את השמור בלי קריאה. כפתור "עדכון" מופיע רק כשנוסף רגע או השתנתה תשובה.
- הכפתורים ננעלים בזמן קריאה (אותו דפוס token שיש היום ל-`startReflectionEngine`).

## 5. סיכונים ותלויות

1. **`HeroDream.tsx` גדול ורגיש.** ההוספה תהיה דרך מכונת מצבים טהורה ונפרדת (`exploration.ts`, נבדקת ביחידה), עם **דגל** (`VITE_DREAM_MAP`). כשהדגל כבוי, המסע הנוכחי רץ כמו שהוא. זה גם ה-rollback.
2. **מדיניות RLS לעדכון `dreams` לא נמצאת בריפו.** לפי `restore-grants.sql` יש הרשאת UPDATE לבעלים. צריך לאמת בקריאה בלבד (`pg_policies`) לפני שבונים המשך מהארכיון. העדכון יהיה קריאה, מיזוג וכתיבה עם `rev` (נעילה אופטימית), כדי ששתי לשוניות לא ידרסו זו את זו.
3. **אילוץ על `label_count`**: לא מאומת. קובע אם אפשרות א אפשרית.
4. **איכות:** עברית לא חלקה, פרטים מומצאים שלא ברשימת הבדיקה, וקשרים "פסיכולוגיים" מאולצים. כל הבדיקות הקיימות (`reflectionChecks`, פנייה מגדרית, אבחנה) יופעלו גם על הקריאות החדשות, וקשר בלי בסיס נמחק.
5. **אורך החוויה:** כל קריאה לוקחת 2–5 שניות (חציון הפרשנות 4.3 שניות). צריך להחזיק את המשתמשת בלי עייפות: שאלה אחת לרגע, הבהרה רק כשבאמת צריך.
6. **חלומות ישנים**: לקריאה בלבד, בלי מפה ובלי המשך (אין להם `attemptId`). לא ימציאו להם תובנות.
7. **אורחים** (כבוי כברירת מחדל): החלום החינמי "מושלם" במסירת התובנה הראשונה, במקום מסירת הפרשנות.
8. **12 פונקציות Vercel**: הכול עובר דרך `mode` בפונקציות קיימות.

## 6. תוכנית בדיקות
- **יחידה:** `mapLayout` לכל כמות רגעים, 1–6 וגם 7 ומעלה כגיבוי. מכונת המצבים. `excerpt`. מיפוי ל-payload ותאימות לאחור (חלומות ישנים, `exploration` חלקי). אימות הקשרים. מניעת שאלה חוזרת. מפתחות cache.
- **שרת:** הנתיבים החדשים: מכסה, החזר מקום במונה בכישלון, `limit_reached`, בעלות על ה-attempt, `basedOn` שמונע קריאה כפולה.
- **"תמונה אחת":** בדיקה שהנתיבים החדשים לא מייבאים את יצירת התמונה. בדיקת דפדפן דרך יומן הגשר (`/__bridge/log`) שבסוף מסע מלא הייתה בדיוק בקשת תמונה אחת. בדיקה שכרטיסים לא מכילים `<img>`.
- **SQL** (רק באפשרות ב): PGlite, כמו המיגרציות הקודמות.
- **דפדפן:** הגשר המקומי, נתונים סינתטיים. רוחבים 360, 375, 390, 768, 1280, 1440 ו-1920, בעברית ובאנגלית. מקלדת בלבד. reduced motion. אין גלילה אופקית (`scrollWidth`). אין חפיפות (בדיקת bounding boxes בקוד). ניגודיות נמדדת.
- **תרחישים:** דילוג על הבהרה, כישלון בכל קריאה (`/__bridge/fail`), רענון, יציאה, ארכיון והמשך, עדכון מבט שלם, 1, 2, 4 ו-6 רגעים, חלום ישן.
- **איכות:** הרחבת `scripts/aiJourneyEval.ts` למסע רב-רגעים על חלומות סינתטיים בלבד, עם מדידת טוקנים. זו הוצאה קטנה ואמיתית מול OpenAI, ואבקש אישור לפני ההרצה. שלוש דוגמאות מלאות: קצר (חלום 10, "סוס לבן במטבח"), עשיר (חלום 7, החתונה והמפתח) ורגיש (חלום 9, בית החולים ואבא). לכל אחת: רגעים, שאלות, תשובות מדומות, תובנות, קשרים ומבט שלם.
- `tsc -b`, `npm run build`, `npm test` (היום 67 קבצי בדיקה) ו-`npm run lint`.
